## Implementation and verification

This is a static HTML/CSS/JavaScript PWA. Content is JSON; `app/engine.js` owns
the player, `app/home.js` owns navigation, `app/common.js` owns local progress
and spaced review, and `app/sync.js` owns Firebase sync. `app/math*.js` and
`app/math.css` own the Mathematics stages and widgets. Source records, maps
and tappable entities are shared. Course entries use `kings` even for topics
that are not rulers. Eras use numeric `from`/`to` ranges.

Before editing, find what owns the file:

| To change | Edit | Do not edit |
|---|---|---|
| Mathematics content | `scripts/build_math_course.py`, `scripts/math_course/` | `math-*` lessons, its course, bank or skills JSON |
| Other released lessons | `content/lessons/<id>.json` | `docs/authoring/`: see below |
| Course outline or catalog | `content/courses/`, `content/catalog.json` | |
| Constitution or Indian History bank | Lesson steps, then that course's `build_*_bank.py` | The bank JSON |
| Generated by `build.py` | Nothing: run the build | `content/manifest.json`, `content/history-reference.json`, the `sw.js` version, `@480` thumbnails |

`scripts/README.md` lists every script and whether it is safe to rerun.
`scripts/archive/` holds finished migrations: never run them. `docs/authoring/`
holds the briefs and scripts that created released lessons. Do not rerun them
against a released course: the Indian History scripts reset it to a draft, and a
rerun can overwrite later edits. Follow the course document if a rebuild is
truly required. Only `.html`, `app/`, `content/`, `icons/` and the root site files
ship, so moving a file under those paths needs a check of `sw.js` and the
deploy script.

Run `scripts/verify.sh` before delivery. It runs `build.py`, which validates
references and assets, creates missing image thumbnails, regenerates the manifest
and stamps the service-worker version, then every automated check. None of this
verifies historical accuracy or fluent Assamese. For new units also run
`scripts/audit_lessons.py` with their paths.
Use the existing `scripts/autoplay.js` browser helper for meaningful player
checks in English and Assamese, including mistakes/retries and first-attempt
80% gates. Test-outs and checkpoints must not retry questions.

Keep user-owned untracked files, including the pre-existing
`scripts/preview_drafts.py`. Do not run its hard-coded external output path
without inspecting it. Keep previews and browser artifacts out of commits.
`output/` is also user-owned and must be preserved. Disposable ignored browser
and Python caches may be cleaned after confirming they are generated artifacts.
Record cleanup decisions in `docs/CLEANUP.md`.
